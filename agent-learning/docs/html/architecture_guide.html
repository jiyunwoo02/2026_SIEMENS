세 가지 개념

세 개념은 순서대로 발전합니다. Tool Calling이 기반이고, MCP는 도구 연결을 표준화하며, Agent는 Tool Calling을 자율적으로 반복합니다.

CONCEPT 01

Tool Calling

LLM이 외부 함수를 "직접 실행"하지 않습니다. 어떤 함수를, 어떤 인자로 호출할지 JSON으로 선언하면 앱 코드가 실제로 실행합니다.

단방향 1~2회
CONCEPT 02

MCP

Tool Calling의 도구 연결을 USB처럼 표준화한 프로토콜입니다. 한 번 서버를 만들면 Claude Desktop, Cursor 등 모든 MCP 클라이언트에서 사용할 수 있습니다.

표준 광고 프로토콜
CONCEPT 03

ReAct Agent

목표를 받으면 LLM이 스스로 단계를 분해하고 도구를 N번 반복 호출합니다. 개발자가 순서를 하드코딩하지 않아도 됩니다.

자율 N회 루프
💡
핵심 원칙 — LLM은 함수를 실행하지 않는다

LLM은 JSON을 반환할 뿐입니다. 앱 코드가 함수를 실행한 뒤 결과를 role="tool" 메시지로 대화 히스토리에 추가해야 LLM이 다음 답변에서 그 결과를 활용할 수 있습니다.

계층 구조

책임을 3개 계층으로 분리합니다. 역방향 의존은 없습니다.

Tool Calling 구현

구현 위치: 01_tool_calling/basic.py

예시 질의: "야간 2라인의 결함률을 조회하고, 2.5%를 초과하면 HIGH 심각도로 알림 보내줘"

전체 흐름 (5단계)

1
도구 정의 — JSON Schema 작성
앱 코드가 LLM에게 "이런 함수를 쓸 수 있다"고 알려주기 위해 tools/schemas.py에 JSON Schema를 작성합니다.
2
1차 LLM 호출 — 도구 선택
finish_reason: "tool_calls" → LLM이 어떤 함수를, 어떤 인자로 호출할지 JSON으로 반환합니다. 함수는 실행하지 않습니다.
3
앱 코드 함수 실행
execute_tool()가 REGISTRY_BASIC에서 함수를 꺼내 실행합니다. 결과를 role="tool" 메시지로 대화 히스토리에 추가합니다.
4
2차 LLM 호출 — 결과 판단
결함률 2.91% > 2.5% 임을 판단하고 다음 도구(create_alert)를 선택합니다. 앱 코드가 다시 실행합니다.
5
3차 LLM 호출 — 최종 답변
finish_reason: "stop" → 루프 종료. 지금까지의 결과를 종합한 한국어 답변을 생성합니다.

            "required": ["shift", "production_line"],

    },

01_tool_calling/basic.py — 루프 핵심 Python 
def chat_with_tools(user_message: str) -> str:
    messages = [
        {"role": "system", "content": _SYSTEM_PROMPT},
        {"role": "user",   "content": user_message},
    ]

    while True:
        response      = call_llm(messages, tools=TOOLS_BASIC)
        finish_reason = get_finish_reason(response)
        message       = get_message(response)

        if finish_reason != "tool_calls":
            break                       # finish_reason="stop" → 최종 답변

        for tc in message["tool_calls"]:
            name   = tc["function"]["name"]
            args   = json.loads(tc["function"]["arguments"])
            result = execute_tool(name, args, REGISTRY_BASIC)

            messages.append({
                "role":         "tool",
                "tool_call_id": tc["id"],  # LLM이 어느 호출의 결과인지 매핑
                "content":      result,
            })

    return extract_text(response)
⚠️
tool_call_id 매핑이 필수입니다

tool_call_id를 빠뜨리면 LLM이 어떤 도구의 결과인지 알 수 없어 오류가 발생합니다. 항상 LLM이 반환한 tc["id"]를 그대로 돌려줘야 합니다.

구현 위치: 01_tool_calling/with_ml_api.py

def predict_defect_rate(
    production_line: str, shift: str, supplier_code: str,
    planned_quantity: int, ambient_humidity_pct: float,
    # ... 12개 파라미터
) -> dict:
    row = {
        "production_line":   production_line,
        "shift":             shift,
        # ... 12개 필드 조립
    }

    # HTTP 호출은 core/ml.py에 위임 — 비즈니스 로직 분리
    defect_pct = call_ml_api(row)

    return {
        "mode":                      "mock" if (MOCK_ML or not ML_URL) else "real",
        "prediction_defect_rate_pct": defect_pct,
    }
core/ml.py — ML API HTTP 호출 Python 
def call_ml_api(row: dict) -> float:
    if MOCK_ML or not ML_URL:
        return _mock_predict(row)       # MOCK_ML=true 시 자동 사용

    with httpx.Client(verify=False) as client:    # 자체서명 SSL
        resp = client.post(
            ML_URL,
            json={"data": [row]},
            headers={"x-api-key": API_KEY},
        )
        result = resp.json()
        return result["data"][0]["prediction(defect_rate_pct)"]
ℹ️
Mock 모드로 먼저 테스트하세요

ML API 없이도 MOCK_ML=true python 01_tool_calling/with_ml_api.py로 전체 흐름을 확인할 수 있습니다. core/ml.py의 _mock_predict가 공구 마모·정비 경과일을 기반으로 결함률을 계산합니다.

from mcp.server.fastmcp import FastMCP
from tools.functions import get_shift_stats as _get_shift_stats

mcp = FastMCP("defect-predictor-mcp")

@mcp.tool()
def get_shift_stats(shift: str, production_line: str) -> dict:
    """
    특정 교대조와 생산 라인의 과거 6개월 평균 결함률을 조회합니다.

    Args:
        shift: 교대조 (DAY 또는 NIGHT)
        production_line: 생산 라인 코드 (LINE-BPR-01 또는 LINE-BPR-02)
    """
    # 실제 구현은 tools/functions.py에 위임
    return _get_shift_stats(shift=shift, production_line=production_line)

# 실행 모드 선택
if "--port" in sys.argv:

else:

ReAct Agent 구현

구현 위치: 03_agent/react_agent.py

예시 목표: "1라인과 2라인의 주간·야간 교대조 결함률을 모두 조회하고, 2.5%를 초과하는 조합은 HIGH 심각도로 알림을 발송해줘"

ReAct 루프 구조

03_agent/react_agent.py — run_agent() Python 
MAX_STEPS = 15  # 무한 루프 방지

def run_agent(goal: str) -> str:
    messages = [
        {"role": "system", "content": _SYSTEM_PROMPT},
        {"role": "user",   "content": goal},
    ]

    while step < MAX_STEPS:
        step += 1
        response      = call_llm(messages, tools=TOOLS_AGENT)
        finish_reason = get_finish_reason(response)
        message       = get_message(response)

        if finish_reason != "tool_calls":
            break                   # 최종 답변 → 루프 종료

        # Thought: LLM의 판단 내용 출력
        if message.get("content"):
            print(f"💭 Thought: {message['content']}")

        # Action + Observation
        for tc in message["tool_calls"]:
            result = execute_tool(tc["function"]["name"], args, REGISTRY_AGENT)
            messages.append({
                "role": "tool", "tool_call_id": tc["id"], "content": result
            })
    else:
        # MAX_STEPS 초과 시 강제 종료
        messages.append({"role": "user", "content": "지금까지의 결과를 종합해줘."})
        response = call_llm(messages)
