# 로컬 예측 UI 구현 상세

> 문서 범위: `aihub/web/index.html`, `app.js`, `style.css`, `ui.sh`와 이들이 사용하는 API 계약. 현재 소스 기준으로 작성했으며 UI 로직을 변경하지 않았습니다.

## 1. 목적과 구조

생산 조건을 자연어로 입력하고 결함률 예측 결과를 확인하는 로컬 테스트 화면입니다. 부족한 조건을 다음 발화로 보완하거나 같은 대화에서 조건을 변경할 수 있습니다.

- 프런트엔드: HTML, CSS, 일반 JavaScript. 별도 npm 패키지 설치·번들링 단계가 없습니다.
- 서버: FastAPI가 UI와 API를 같은 출처에서 제공합니다. 별도 프런트엔드 서버나 CORS 설정 없이 사용하는 구조입니다.
- 처리: 브라우저 → 대화 API → LLM 조건 추출 → 슬롯 병합·검증 → 필요 시 ML 예측 → 선택적으로 LLM 해설 → 브라우저 표시.
- 브라우저가 외부 LLM/ML을 직접 호출하지 않습니다. 인증 설정은 서버가 읽습니다.

| 경로 | 역할 |
| --- | --- |
| `aihub/web/index.html` | 화면 구조, DOM ID, 안내문, 접근성 속성 |
| `aihub/web/app.js` | 이벤트, 요청, 탭 내 세션 상태, 결과·오류 렌더링 |
| `aihub/web/style.css` | 색상, 카드, 입력 폼, 반응형 배치, 포커스 표시 |
| `aihub/web/ui.sh` | 개발용 Uvicorn 실행 명령 한 줄 |
| `aihub/api.py` | 정적 파일 제공, 상태 조회, 대화 처리, 세션 삭제 |
| `aihub/config.py` | 환경 설정 로드·검증·캐시 |
| `aihub/pipeline.py` | 슬롯 수집, 상태 결정, 예측·해설 조율 |
| `test/test_api.py` | 정적 라우트 및 API 계약 테스트. 브라우저 테스트는 아님 |

입력 필드의 정의·범위는 [입력 스키마](input_schema.md), 서버 설계는 [아키텍처](architecture.md), 다른 실행 방식은 [실행 가이드](run.md)를 참고하세요.

## 2. 설치와 실행

### 전제 조건

- Python과 가상환경을 준비합니다. 현재 `pyproject.toml`에는 지원 Python 버전 범위가 선언되어 있지 않으므로 사용하는 환경에서 설치·테스트 확인이 필요합니다.
- 주요 의존성은 `requirements.txt`의 `fastapi`, `uvicorn[standard]`, `pydantic`, `pydantic-settings`, `python-dotenv`, `httpx`이며 테스트에는 `pytest`를 사용합니다. 기재된 버전은 최소 버전 제약이며 고정된 설치 버전이 아닙니다.
- 브라우저에서 JavaScript를 허용해야 합니다. `fetch`, `AbortController`, `Object.hasOwn`, `replaceChildren` 등을 사용하며 브라우저별 호환성 검증은 별도로 필요합니다.

워크스페이스 루트에서 시작하는 PowerShell 예시입니다. 이미 준비된 가상환경이 있으면 해당 Python을 사용하고 생성 단계는 생략하세요.

```powershell AIHUB/docs/web_ui.md
cd AIHUB
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn aihub.api:app --reload --host 127.0.0.1 --port 8000
```

서버 시작 후 `http://127.0.0.1:8000/`에 접속합니다. `index.html`을 파일로 직접 열지 마세요. 정적 파일과 API 경로가 서버 루트 기준이기 때문입니다.

### `ui.sh`의 의미와 작업 디렉터리

가상환경의 `python`을 사용하는 상태에서 **`AIHUB` 디렉터리 기준**으로 실행합니다. Bash 환경에서는 다음과 같이 실행할 수 있습니다.

```bash AIHUB/aihub/web/ui.sh
bash aihub/web/ui.sh
```

PowerShell에서는 `.sh` 실행 대신 동일한 명령을 직접 사용합니다.

```powershell AIHUB/aihub/web/ui.sh
python -m uvicorn aihub.api:app --reload --host 127.0.0.1 --port 8000
```

| 옵션 | 의미 |
| --- | --- |
| `python -m uvicorn` | 해당 Python 환경의 Uvicorn 모듈 실행 |
| `aihub.api:app` | `aihub/api.py`의 FastAPI 객체 `app` 사용 |
| `--reload` | 개발용 코드 변경 감지·재시작. 재시작 시 서버 세션 소실 |
| `--host 127.0.0.1` | 로컬 루프백 주소에 바인딩 |
| `--port 8000` | 접속 포트 지정 |

`ui.sh`에는 가상환경 활성화, 패키지 설치, 디렉터리 이동, 환경 변수 설정이 없습니다. `aihub/web`으로 이동한 뒤 실행하는 스크립트가 아닙니다.

### 서버 설정

`Settings`는 **현재 작업 디렉터리의 `.env`**를 읽습니다. 위 실행 방식에서는 `AIHUB/.env`가 대상이며 환경 변수가 파일 값보다 우선합니다. 실제 비밀값을 문서·소스·브라우저 입력에 넣지 말고 로컬 환경 변수 또는 보호된 설정 파일로 관리하세요.

| 설정 | 용도 |
| --- | --- |
| `api_key` 또는 `llm_api_key` | LLM 인증 키. 실제 질의 처리에 필요 |
| `LLM_MODEL` | 사용할 LLM 모델. 실제 질의 처리에 필요 |
| `AI_HUB_ENDPOINT_URL` | 실제 ML 모드에서 필요한 예측 주소 |
| `AI_HUB_API_KEY` | ML 서비스에서 인증을 요구할 때 사용 |
| `MOCK_ML` | 기본 `false`. `true`이면 ML만 더미 결과로 대체 |

**`MOCK_ML=true`여도 자연어 추출은 실제 LLM을 호출합니다.** 예측 단계에 도달하면 모의 ML은 조건 순서대로 `1.65%`, `2.65%`, …를 반환합니다. 해설 체크를 꺼도 자연어 추출은 생략되지 않습니다.

정적 화면 조회는 예측 파이프라인을 초기화하지 않습니다. 다만 서버 시작 시 설정 객체를 읽으므로 설정 타입 자체가 잘못된 경우까지 시작을 보장하는 것은 아닙니다. 설정은 프로세스에 캐시되므로 변경 후 서버를 재시작하세요. `.env` 수정만으로 자동 재시작된다고 가정하지 마세요.

## 3. 화면 구성 (`index.html`)

CSS는 `/ui-assets/style.css`, JavaScript는 `/ui-assets/app.js`에서 불러옵니다. 스크립트는 `defer`로 HTML 파싱 이후 실행되며, JavaScript 비활성화 시 `noscript` 안내가 표시됩니다.

| 영역 / DOM ID | 표시·입력 내용 |
| --- | --- |
| `reset` | 현재 대화를 삭제하고 새 대화 화면으로 초기화 |
| `health` | 실제/모의 ML 모드, 필수 설정 존재 여부 |
| `messages` | 사용자와 AIHUB 메시지 로그 |
| `chat-form`, `query` | 자연어 질의 폼과 필수 입력란 |
| `example-full`, `example-partial` | 전체 조건 예제 / 라인만 지정하는 추가 질문 예제 |
| `explain`, `send` | LLM 해설 선택(기본 체크), 질의 전송 |
| `progress`, `error` | 진행·소요 시간 안내, 오류 경고 |
| `session`, `result-status` | 세션 ID·처리 턴, 현재 처리 상태 |
| `predictions`, `latency` | 조건별 예측 카드, ML 클라이언트 보고 시간 |
| `missing`, `known` | 누락 필드 목록, 서버가 보관한 확인값 JSON |
| `raw` | 접기/펼치기 가능한 대화 API 응답 JSON |

`raw`는 외부 ML 서비스의 원본 응답이 아니라 **`/chat/predict`의 응답**입니다. `known_slots`는 세션의 공통 확인값이며 조건별 최종 입력 전체와 같지 않을 수 있습니다. 조건별 입력은 응답의 `model_input`을 확인하세요.

접근성 관련 구현은 `lang="ko"`, 입력 레이블, `role="log"`·`aria-live="polite"`, 상태 영역의 `role="status"`, 오류 영역의 `role="alert"`, 폼의 동적 `aria-busy`, 키보드 포커스 테두리입니다. 보조기기 실사용 검증이나 접근성 표준 준수를 보증하는 것은 아닙니다.

## 4. 사용자 흐름과 상태 관리 (`app.js`)

스크립트는 엄격 모드의 즉시 실행 함수 안에서 동작합니다. `ui`는 DOM ID를 요소에 매핑하며, `sessionId`와 `busy`는 함수 내부 상태입니다. DOM 요소 누락을 별도로 검사하지 않으므로 HTML ID 변경 시 JS도 함께 확인해야 합니다.

### 최초 진입과 예제

1. 이벤트를 등록하고 첫 안내 메시지를 추가합니다.
2. `/health`를 한 번 조회합니다. 자동 주기 갱신은 없습니다.
3. 예제 버튼은 입력란을 채우고 포커스만 이동합니다. 전송하거나 세션을 초기화하지 않습니다.
4. 추가 질문 흐름을 테스트하려면 **새 대화 → 추가 질문 예제 → 질의 보내기** 순서로 사용합니다. 기존 슬롯이 있으면 누락 항목이 없을 수 있습니다.

### 질의 전송

1. 기본 폼 제출을 막고 `busy`이면 종료합니다. 입력 앞뒤 공백을 제거하고 빈 질의를 차단합니다.
2. 이전 오류와 최신 결과를 비운 뒤 사용자 메시지를 로그에 추가합니다. 이전 대화 로그는 유지합니다.
3. 전송·초기화·입력·해설·예제 버튼을 비활성화하고 진행문을 표시합니다.
4. 현재 `sessionId`와 해설 선택을 포함해 `/chat/predict`로 한 번 요청합니다.
5. 응답을 렌더링하고 `ok`, `need_more_info`이면 입력란을 비웁니다. 다른 상태나 요청 실패 시 입력을 보존합니다.
6. 성공적으로 응답을 표시한 경우 전체 응답 시간을 기록합니다. 실패하면 경고와 실패 메시지를 표시합니다.
7. 마지막으로 컨트롤을 활성화하고 입력란에 포커스를 돌립니다.

브라우저의 전체 응답 시간은 `performance.now()`로 요청 직전부터 결과 렌더링 후까지 측정합니다. `latency_ms`와 다릅니다. 실제 ML 클라이언트 보고 시간은 마지막 호출 시도의 클라이언트 생성·정리를 포함하고 이전 시도·재시도 대기·LLM 처리 시간은 제외합니다. 모의 ML은 `0 ms`입니다.

### 새 대화와 세션 수명

- `sessionId`가 있으면 서버 세션 삭제를 먼저 요청합니다. 성공 또는 404일 때 로컬 화면과 ID를 초기화합니다.
- 다른 삭제 오류에서는 기존 대화·결과·입력을 보존합니다. 삭제 버튼 처리 중에는 다른 입력을 막습니다.
- 초기화는 해설 체크 상태를 변경하거나 `/health`를 재조회하지 않습니다. 서버의 새 세션은 다음 질의 때 만들어집니다.
- 브라우저는 세션 ID를 JS 메모리에, 메시지를 DOM에 보관합니다. `localStorage`, `sessionStorage`, 쿠키로 복원하지 않습니다.
- 새로고침·탭 종료 시 UI는 복원되지 않지만 서버 세션 삭제 요청도 보내지 않습니다.
- 서버 세션은 프로세스 메모리에만 존재하고 재시작 시 사라집니다. 만료·영속 저장·워커 간 공유 기능이 없습니다.
- 서버에 없는 ID로 질의하면 그 ID의 새 세션을 만듭니다. 서버 재시작 후 화면에 남은 ID를 전송해도 이전 슬롯이 복원되는 것은 아닙니다.
- `turn`은 메시지 개수가 아니라 슬롯 `merge()` 호출 횟수입니다. 자연어 추출 실패는 증가시키지 않습니다.

## 5. JavaScript 함수 명세

DOM 갱신 함수는 의미 있는 반환값 대신 화면·상태를 변경합니다. 비동기 함수는 Promise를 반환합니다.

| 함수 | 입력 | 출력·부작용 / 예외 처리 |
| --- | --- | --- |
| `addMessage(kind, text)` | 메시지 종류·문자열 | `article`, `strong`, `p`를 생성해 로그에 추가하고 스크롤. 사용자 외 종류의 제목은 AIHUB |
| `setBusy(value, message = "")` | 처리 여부·안내문 | `busy`, 6개 컨트롤의 `disabled`, 폼 `aria-busy`, 진행문 갱신 |
| `showError(message = "")` | 오류 문자열 | 오류 텍스트 설정. 빈 문자열이면 `hidden=true` |
| `request(path, options = {})` | URL 경로·fetch 옵션 | 파싱된 JSON 반환. DELETE 404는 `null`. 연결·JSON·HTTP 오류는 `Error` 전달 |
| `clearResult()` | 없음 | 예측·누락·확인값·상세 JSON·ML 시간 초기화. 세션·상태 문구·메시지는 호출자가 별도 처리 |
| `renderResult(body)` | 대화 API 응답 | 원본 JSON 표시 후 기본 계약 검사, 세션·상태·결과 갱신, AIHUB 메시지 추가. 계약 불일치 시 `Error` |
| `submit(event)` | 폼 제출 이벤트 | 검증·전송·렌더링 수행. 오류를 UI에 표시하고 `finally`에서 입력 잠금 해제 |
| `reset()` | 없음 | 서버 세션 삭제 후 UI 초기화. 삭제 실패 시 기존 상태 보존 |
| `checkHealth()` | 없음 | 설정 배너 갱신. 10초 타이머로 요청 중단 시도. 실패도 배너에 표시하고 타이머 해제 |
| `fillExample(text)` | 예제 문자열 | 처리 중이 아닐 때 입력란에 채우고 포커스 이동. API 호출 없음 |

`request()`는 기본적으로 `cache: "no-store"`를 전달합니다. HTTP 오류 본문의 `detail`이 문자열일 때만 해당 내용을 표시합니다. FastAPI 검증 오류처럼 배열이면 일반 실패 안내를 사용합니다. DELETE 404 외에는 JSON 파싱을 수행하므로 현재 계약을 204 무본문 응답으로 바꾸려면 클라이언트도 수정해야 합니다.

## 6. API 계약과 렌더링

| 메서드·경로 | 요청 | 응답과 UI 용도 |
| --- | --- | --- |
| `GET /` | 없음 | `index.html`, `Cache-Control: no-cache` |
| `GET /ui-assets/{파일}` | 없음 | `web` 디렉터리의 정적 파일 |
| `GET /health` | 없음 | `status`, `mock_ml`, `endpoint_configured`, `llm_configured`, `active_sessions`. UI는 모드와 두 설정 여부 사용 |
| `POST /chat/predict` | JSON: `query`, `session_id`, `explain` | 파이프라인 결과와 세션 정보 |
| `DELETE /chat/session/{session_id}` | 없음 | 삭제 시 `status: reset`, `session_id`; 없는 세션은 HTTP 404 |

### 대화 요청

| 필드 | 타입·기본값 | 설명 |
| --- | --- | --- |
| `query` | 필수 문자열 | UI에서 trim 후 전송. 서버도 빈 값·공백 질의 차단 |
| `session_id` | 문자열 또는 null, 기본 null | UI 첫 질의는 null, 이후 응답에서 받은 ID 사용 |
| `explain` | boolean, 기본 true | 성공한 예측의 LLM 해설 여부. 자연어 추출을 끄지 않음 |

### 대화 응답

| 필드 | 서버 계약 / UI 처리 |
| --- | --- |
| `status` | 아래 5개 상태 중 하나. UI는 허용 목록 검사 |
| `answer` | 문자열 필수. 대화 로그에 일반 텍스트로 출력 |
| `session_id` | 비어 있지 않은 문자열 필수. 다음 요청에 재사용 |
| `turn` | 서버 처리 턴. UI는 값을 표시하지만 타입을 별도 검증하지 않음 |
| `predictions` | 숫자 배열. 유한한 number만 소수점 둘째 자리의 `%` 카드로 표시 |
| `unit` | 서버는 `percent` 반환. UI는 이를 검사하지 않고 퍼센트 단위로 표시 |
| `missing_fields` | 누락 필드 배열. 빈 경우 성공은 `없음`, 나머지는 답변·오류 확인 안내 |
| `known_slots` | 확인값 객체. 없거나 falsy이면 `{}`를 표시 |
| `model_input` | 조건별 입력 배열. 별도 편집기는 없고 상세 JSON에서 확인 |
| `errors` | 오류 문자열 배열. 오류 상태에서 비어 있으면 `answer`로 대체 |
| `latency_ms` | ML 클라이언트 보고 시간. `ok`일 때만 전용 영역에 표시 |

`1.65`는 `1.65%`로 표시하며 100을 곱하지 않습니다. 잘못된 숫자는 해당 카드에 `유효하지 않은 예측값`으로 표시합니다. 응답 전체에 대한 엄격한 스키마 검증은 없으며 기본 계약 검사는 `status`, `answer`, `session_id`에 한정됩니다.

### 처리 상태와 HTTP 오류의 구분

| `status` | 의미 | ML 단계 | UI 동작 |
| --- | --- | --- | --- |
| `ok` | 예측 완료 | 실제 또는 모의 ML 성공 | 결과·ML 시간 표시, 입력 비움 |
| `need_more_info` | 필수값 부족 | 미호출 | 누락 필드·추가 질문 표시, 입력 비움 |
| `invalid_input` | 수집된 값 검증 실패 | 미호출 | 오류 표시, 입력 유지 |
| `endpoint_error` | ML 처리 실패 | ML 단계 진입 후 실패 | 오류 표시, 입력 유지 |
| `llm_error` | 자연어 추출 실패 | 미호출 | 오류 표시, 입력 유지 |

위 상태들은 현재 API에서 HTTP 200으로 전달될 수 있습니다. HTTP 성공을 예측 성공으로 판단하지 마세요. 해설 생성만 실패한 경우 파이프라인은 수치 답변으로 대체하고 `ok`를 유지합니다.

별도의 요청 오류에는 HTTP 422(요청 검증), HTTP 503(필수 설정 등 파이프라인 초기화 실패), 연결 오류, JSON이 아닌 응답, 예상과 다른 응답 계약이 있습니다. 제출 시 이러한 오류를 잡으면 최신 질의 결과를 확인하지 못했다는 문구를 표시합니다.

## 8. 오류 대응·보안·현재 제약

- **자동 재전송 없음:** 브라우저는 실패한 질의를 자동 재전송하지 않습니다. 연결이 끊겨도 서버 처리는 진행될 수 있고 수동 재전송은 중복 처리를 유발할 수 있습니다. 서버 ML 클라이언트의 재시도 설정은 별개입니다.
- **취소·타임아웃:** UI에 질의 취소 기능이 없습니다. `/health`에는 10초 중단 타이머가 있지만 대화 POST·세션 DELETE에는 클라이언트 타임아웃이 없습니다. 오래 대기하면 입력 잠금도 유지될 수 있습니다.
- **텍스트 출력:** 외부 응답과 입력은 `textContent`로 넣으며 HTML·Markdown으로 해석하지 않습니다. 답변의 `**`나 코드 펜스도 문자로 보입니다. 이는 해당 렌더링 경로의 HTML 실행을 방지하는 조치이지 전체 시스템 보안 보증은 아닙니다.
- **설정 확인 한계:** 배너는 설정 존재 여부만 확인합니다. 누락 경고가 있어도 전송을 막지는 않으며 서버 오류로 이어질 수 있습니다.
- **민감 정보:** 질의·입력 조건은 설정된 외부 서비스로 전송될 수 있습니다. 응답·상세 JSON·로그에 입력값이나 오류 원문이 포함될 수 있으므로 공유 전 확인하세요.
- **로컬 사용 전제:** 현재 API 코드에는 사용자 인증·세션 소유권 검증이 없습니다. 공개 서비스로 노출하지 마세요. 운영 배포에는 인증, 접근 제어, HTTPS, 요청 제한, 세션 저장·만료 정책 등을 별도로 설계해야 합니다.
- **정적 폴더:** `web` 전체를 정적으로 제공하므로 `ui.sh`도 정적 접근 대상입니다. 이 폴더에 키·`.env`·내부 자료를 넣지 마세요.
- **대화 저장 없음:** 내보내기·복원·서버 대화 로그 조회·자동 세션 만료 기능은 구현되지 않았습니다. 탭 내 중복 클릭 방지는 여러 클라이언트가 같은 서버 세션을 동시에 사용하는 상황까지 해결하지 않습니다.
- **배포 경로:** `/ui-assets`, `/health`, `/chat/...`는 루트 절대 경로입니다. 하위 URL 경로에 배포할 경우 프록시·경로 설정 변경이 필요합니다.

## 9. 검증 방법과 확인 범위

### 기존 자동 테스트

가상환경을 활성화한 상태로 `AIHUB`에서 실행합니다.

```powershell AIHUB/docs/web_ui.md
python -m pytest test/test_api.py
python -m pytest
```

`test/test_api.py`는 정적 HTML/JS/CSS 제공, 없는 파일·경로 이탈 요청의 404, 설정 요약, 세션 유지·삭제, 상태 전달, 빈 질의의 422, 초기화 실패의 503을 테스트합니다. 파이프라인을 대역으로 교체하므로 실제 LLM/ML은 호출하지 않습니다.

이 테스트는 브라우저에서 JavaScript를 실행하지 않습니다. 따라서 버튼 동작·실제 DOM 렌더링·반응형 표시·스크린리더 동작·외부 서비스 연결까지 검증했다고 해석하면 안 됩니다.

### 수동 확인 체크리스트 (실행 결과가 아닌 검증 절차)

| 시나리오 | 확인할 사항 |
| --- | --- |
| 첫 접속 | 첫 안내, 설정 배너, 빈 결과 영역, 브라우저 콘솔 오류 여부 |
| 전체 조건 예제 | 클릭만으로 요청되지 않음. 전송 후 상태·카드·JSON 확인. 실제 결과는 LLM/ML에 따라 확인 필요 |
| 추가 질문 | 새 대화 후 부분 예제 전송, 누락 필드 확인, 후속 입력에서 같은 세션 유지 |
| 조건 변경 | 기존 대화에서 일부 값만 바꾸고 `known_slots`·`model_input` 확인 |
| 해설 끄기 | 요청의 `explain=false`, 자연어 추출은 계속 수행 |
| 중복 조작 | 처리 중 전송·새 대화·입력·예제·체크박스 비활성화 |
| 오류 상태 | API 응답 대역으로 5개 상태·HTTP 오류·비JSON·잘못된 계약을 재현해 표시와 입력 보존 확인 |
| 서버 연결 실패 | 사용자 메시지와 입력 보존, 이전 결과 제거, 자동 재전송 없음 |
| 세션 삭제 | 성공·404는 초기화, 다른 오류는 기존 화면 보존 |
| 새로고침 | 화면·세션 ID 복원 없음. 서버 세션의 자동 삭제도 없음 |
| 텍스트 안전성 | 통제된 응답 대역의 HTML 태그가 실행되지 않고 문자로 표시됨 |
| 화면 폭·키보드 | 820px/420px 경계와 좁은 화면에서 배치·스크롤·포커스 확인 |

### 이번 문서화의 검증 기록

- UI 4개 파일, API, 설정, 파이프라인, ML 클라이언트, API 테스트 소스를 대조했습니다.
