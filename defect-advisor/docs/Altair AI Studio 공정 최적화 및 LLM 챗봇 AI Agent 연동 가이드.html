3.2 target 파라미터의 핵심 메커니즘

AI Studio 내부 설정이 optimization direction = minimize, class name = %{target}이므로, target은 "발생 확률을 최소화하고자 하는 대상 클래스"를 뜻합니다.

target 엔진 내부 연산 비즈니스 목적 응답 특징
"1" 불량(1) 확률 최소화 불량을 줄이고 양품률 극대화하는 최적 공정 조건 탐색 예측 라벨 "0"(정상), confidence(1) ≈ 1.7%
"0" 정상(0) 확률 최소화 불량이 유발되기 쉬운 위험 공정 조건 탐색 예측 라벨 "1"(불량), confidence(0) ≈ 1.7%
🚨 매핑 오류 주의
사용자가 "정상 조건을 찾아줘"라고 질의했을 때 target=0(정상)을 전달하면 정상 확률을 최소화하여 불량을 유발하는 조건이 반환됩니다. 사용자 자연어 단어가 아닌 최적화 방향(의도)을 기준으로 매핑해야 합니다.

LLM AI Agent
챗봇 AI Agent 아키텍처 설계
4.1 Intent 정의 — 6종 의도 분류 체계

LLM에게 직접 0 또는 1 같은 숫자를 결정하게 하면 환각(Hallucination) 위험이 큽니다. LLM은 비즈니스 Intent Enum만을 반환하고, 백엔드 코드의 불변 사전(Frozen Dict)을 통해 target으로 결정론적 변환을 수행합니다.

Intent 의미 호출 대상 target
predict 주어진 조건의 결함률 예측 예측 API (ml.py) —
optimize_reduce_defect 불량을 줄이는 최적 조건 탐색 최적화 API (optimization.py) "1"
optimize_find_defect_risk 불량이 잘 나는 위험 조건 탐색 최적화 API (optimization.py) "0"
predict_and_optimize 결함률 예측 + 불량 최소화 조건 탐색 두 API 모두 "1"
predict_and_find_risk 결함률 예측 + 불량 유발 위험 조건 탐색 두 API 모두 "0"
clarify 의도가 불분명해 되묻는 경우 호출 없음 (고정 문구) —
4.2 아키텍처 비교 — 단독 최적화 챗봇 vs 통합형
구분 A. 독립형 최적화 챗봇 (신규 구축) B. 통합형 결함 예측 & 최적화 챗봇 (기존 확장)
연동 엔드포인트 최적화 API 단독 예측 API + 최적화 API 동시 지원
주요 Intent optimize_reduce_defect, optimize_find_defect_risk, clarify 위 3개 + predict, predict_and_optimize, predict_and_find_risk
데이터 추출 요구 공정 조건 추출 불필요 (방향 의도만 판별) 예측 요청 시 공정 피처 12종 추출 및 누락값 질의 로직 유지
선택 근거 빠른 MVP, 단순한 구조 실제 코드 선택. defect-predictor의 슬롯 필링 로직을 재사용
ℹ️ 실제 구현 선택: B. 통합형
실제 코드(pipeline.py)는 통합형 설계를 따릅니다. _gather_and_predict()가 슬롯 병합 → 검증 → ML 호출의 공통 단계를 담당하며, predict_and_* 경로는 최적화 실패 시에도 status="ok"를 반환하는 부분 성공 패턴을 사용합니다.
4.3 Intent → Target 고정 변환 코드
# aihub/optimization.py — INTENT_TO_TARGET 고정 매핑 # LLM이 직접 target 값을 고르지 않음 (환각 방지) INTENT_TO_TARGET: dict[str, str] = { "optimize_reduce_defect": "1", # 불량(1) 확률 최소화 → 양품 조건 탐색 "predict_and_optimize": "1", # 예측 후 불량 최소화 개선 조건 탐색 "optimize_find_defect_risk": "0", # 정상(0) 확률 최소화 → 위험 조건 탐색 "predict_and_find_risk": "0", # 예측 후 불량 유발 위험 조건 탐색 }
⚠️ 자동 테스트 없음 — 변경 시 반드시 교차 검증
이 매핑이 틀리면 최적화 방향이 반대로 뒤집힌다. 변경 시 운영 API로 target=0/target=1 응답을 비교해 교차 검증한다.
Implementation
핵심 구현 패턴
5.1 처리 흐름 — Intent별 API 분기 (pipeline.py)
사용자 질의 → QueryExtractor.extract() LLM 동기 호출, intent + 12개 필드 JSON 추출 → DefectRatePipeline.run() intent 분기 predict → _gather_and_predict() + LLM 해설(선택) predict_and_optimize → _gather_and_predict() → OptimizationClient(target="1") predict_and_find_risk → _gather_and_predict() → OptimizationClient(target="0") optimize_reduce_defect → OptimizationClient(target="1") 만 optimize_find_defect_risk → OptimizationClient(target="0") 만 clarify → 고정 문구 반환, API 호출 없음 → PipelineResult 반환
ℹ️ predict_and_* 경로: LLM 해설 없음
predict 경로는 ML 예측 후 _explain()으로 LLM을 추가 호출한다. 반면 predict_and_optimize/predict_and_find_risk는 _format_predict_and_optimize()(코드 포매터)가 직접 answer를 구성한다. 최적화 실패 시에도 status="ok" 반환 — optimization=null과 errors 필드로 확인.
5.2 Intent → Target 결정론적 변환 파이프라인
▲ 사용자 자연어 → LLM Intent 분류 → 고정 사전 Target 변환 파이프라인
5.3 API 호출 및 메타 키 분리 파싱 (optimization.py)
▲ GET 요청 → Raw JSON 수신 → 공정 조건 / 예측 메타 분리

6.3 주요 이슈 및 해결 이력
Set Macro 오퍼레이터가 외부 target 덮어씀
해결: Set Macro 제거 후 Context 패널(View → Show Panel → Context)에 매크로 선언. ?target=0 쿼리 파라미터가 정상 주입됨을 diff로 확인.
Prescriptive Analytics 무한 대기
해결: limit type = generations & population 설정. population: 10, max generations: 5. Time limit 대안도 동작 확인.
target 매핑 역전 (정반대 조건 반환)
해결: "정상 조건"이라는 사용자 단어를 target=0으로 매핑하면 정상 확률을 최소화해 위험 조건이 반환됨. INTENT_TO_TARGET 사전 기준으로 매핑 방향을 재정립.
SSL 인증서 오류 (사내망 환경)
해결: .env에 AI_HUB_VERIFY_SSL=false / OPTIMIZATION_VERIFY_SSL=false 설정. httpx/requests 클라이언트 모두 적용.

7.1 핵심 대화 시나리오 — 6종 케이스
