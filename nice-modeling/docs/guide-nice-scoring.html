모델 개요

NICE평가정보 신용평가 데이터를 기반으로 LightGBM 이진 분류 모델을 학습하여 고객의 불량 확률을 예측하고, 오즈 로그 스케일링으로 신용점수(0–1000점)를 산출합니다. AI Studio에서 학습하고 AI Hub(mlops)를 통해 REST API로 서빙합니다.

출력 및 신용점수 산출

출력 필드

신용점수 산출 공식

오즈 로그 스케일링(Log Odds Scaling) 방식. 640점 = 정상·불량 확률이 동일한 기준점(odds = 1).

anchor = 640       # 기준 점수
pdo    = 80        # Points to Double the Odds
factor = 80 / ln(2)  ≈ 115.44

odds  = P(0) / P(1)
Score = anchor + factor × ln(odds)
Score = clip(0, 1000).round(0)

AI Studio Generate Attributes 수식 (v2 기준):

Score = max(0, min(1000, round(640 + (115.44 * log(([confidence(0)] + 1e-10) / ([confidence(1)] + 1e-10))), 0)))
LightGBM Extension의 confidence 컬럼명은 confidence(0), confidence(1)입니다 (Python Learner v1의 confidence(conf(0))과 다름). 1e-10은 log(0) 방지용 epsilon이며, 긴 소수(0.0000000001) 표기 시 AI Studio XML 저장에서 자동 줄바꿈이 삽입되어 수식이 깨지는 현상을 방지합니다.

트러블슈팅 이력

#증상원인해결상태
1 Python Learner — missing label 헤더 KEY 앞 공백 → Set Role 충돌 Set Role에서 KEY → id 항목 제거, TARGET → label만 유지 ✅ 해결
2 Python Learner — failed to run python code base conda 환경에 lightgbm 미설치 Python312 환경에 lightgbm==4.6.0 설치 ✅ 해결
3 AI Hub 배포 후 한글 주석·numpy 인코딩 에러 서버 Python Extension 환경 차이 한글 주석 제거, numpy → math 모듈 대체 ✅ 해결
4 AI Hub — ExecutionError: script could not be parsed 서버 Python Extension 미구성 → rm_apply() 실행 불가 LightGBM Extension (JAR)으로 전환 → Python 의존성 제거 ✅ 해결
5 AI Hub — LightGBMModel not registered for deserialization AI Hub 서버에 LightGBM Extension JAR 미설치 서버에 lightgbm_extension-1.0.4-all.jar 설치 ✅ 해결
6 AI Hub — KEY is of value type 'Real' but should be 'Integer' API JSON 입력 숫자는 항상 Real로 파싱 → KEY 타입 불일치 배포 프로세스에 Set Role(KEY → id) 추가 + 재학습·재배포 ✅ 해결
7 AI Hub — attribute 'confidence(conf(0))' is unknown Python Learner와 LightGBM Extension의 confidence 컬럼명 상이 Score 수식을 confidence(0), confidence(1)로 수정 ✅ 해결
8 Score가 수식 문자열 그대로 반환 AI Studio XML 저장 시 긴 소수(0.0000000001)에 자동 줄바꿈 삽입 → 수식 파싱 실패 1e-10 단축 표기로 변경 ✅ 해결
