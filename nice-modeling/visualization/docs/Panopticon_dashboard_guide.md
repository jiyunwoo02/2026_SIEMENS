# NICE 신용점수 Panopticon 대시보드 구축 가이드

슬라이더로 신용 변수 47개를 조절하면 AI Hub 스코어링 모델이 다시 호출되어 신용점수, 불량·정상 확률, target(0/1) 예측이 갱신되는 대시보드입니다. 이 문서는 대시보드를 어떻게 만들었는지, 어떤 기능을 지원하는지, 운영 시 무엇을 알아야 하는지를 정리합니다.

- 결과 파일: `261109_dashboard_v3_sliders.exz` (원본, 서버 버전 2609.1.0.36042)
- 호환 파일: `261110_슬라이더적용_v2_server26.1.exz` (서버 버전 26.1.0.35462 대응, 아래 §5-2 참조)
- 워크북: `261109_Workbook` / 대시보드: `Dashboard1` / 데이터 테이블: `DataTable1`
- 서빙 모델: AI Hub `nice-scoring` 서비스 v2 (`deploy_scoring_process_v02`, LightGBM Extension 1.0.4)

---

## 1. 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 입력 | 슬라이더 47개 (신용 변수, 범위 0~10, 기본값은 기존 샘플 요청 값) |
| 출력 | 신용점수(`Score`), 불량확률(`confidence(1)`), 정상확률(`confidence(0)`), target 예측(`prediction(TARGET)` 0/1), 판정(`Result`), 신용등급 구간(`Grade`) |
| 갱신 방식 | 슬라이더 조작 → 대시보드 파라미터 변경 → 데이터 테이블이 AI Hub 엔드포인트를 다시 호출 → 결과 박스 갱신 |
| 구성 요소 | 슬라이더(NumericActionSlider) 47개, 텍스트 박스(TextBox) 21개 |
| 데이터 소스 | TEXT 데이터 소스 + Python Transform (REST 호출) |

## 2. 전체 구조

```
[슬라이더 47개]                  [데이터 테이블 DataTable1]                   [AI Hub]
 P_R1_CBINQ_CNT05  ─┐            TEXT 소스(입력 48개 컬럼)
 P_R1_CBINQ_...    ─┼─ 파라미터 ─→ Python Transform
 ...               ─┘             · {P_변수명} 자리에 슬라이더 값 치환
                                  · POST  ──────────────────────────────→  nice-scoring v02
                                  · 응답(prediction, confidence, Score) ←──  (Set Role → Apply Model
                                  · Result, Grade 컬럼 계산                    → Generate Attributes)
                                       │
                                       ▼
                         [결과 박스: Score / confidence / target / 판정 / 등급]
```

핵심은 슬라이더가 만든 **대시보드 파라미터**를 데이터 테이블이 **같은 이름의 `{P_변수명}`** 으로 받아 쓴다는 점입니다. 파라미터가 바뀌면 데이터 테이블이 다시 실행되고, 데이터 테이블을 보는 모든 박스가 함께 갱신됩니다.

## 3. 만든 과정

### 3-1. 초안 분석

처음 대시보드는 AI Hub Endpoint 커넥터(`AIHub`)로 연결한 데이터 테이블 1개와 텍스트 박스 몇 개뿐이었습니다. 이 구조에는 두 가지 한계가 있었습니다.

- 요청 본문(`RequestBody`)이 고정 샘플 1건이라 항상 같은 결과만 보입니다.
- 입력을 바꿀 위젯이 없습니다.

### 3-2. 레퍼런스 분석

변수를 직접 조절하는 레퍼런스 워크북(HT 목상해 예측 플랫폼)을 분석해 다음을 확인했습니다.

| 항목 | 레퍼런스 방식 |
| --- | --- |
| 입력 위젯 | `NumericActionSlider`(수치), `ActionDropDown`(범주) |
| 위젯과 파라미터 연결 | 위젯 속성 `DashboardParameterName`에 파라미터 이름 지정, `ActionPartTriggerMode = Parameter` |
| 파라미터 정의 | 대시보드와 데이터 테이블 양쪽에 같은 이름의 `parameter`(이름, 기본값, 타입) 선언 |
| 모델 호출 | TEXT 데이터 소스 + Python Transform. 스크립트 안의 `{P_변수명}`이 파라미터 값으로 치환 |
| 결과 표시 | 데이터 모드 텍스트 박스가 데이터 테이블의 컬럼을 표시 |
| 범주형 선택지 | 값 목록을 가진 별도 TEXT 데이터 테이블을 드롭다운의 소스로 사용 |

### 3-3. 데이터 테이블 재구성

기존 AI Hub Endpoint 커넥터를 레퍼런스와 같은 TEXT + Python Transform 구조로 바꿨습니다.

1. **TEXT 데이터 소스**: 헤더(`KEY` + 변수 47개)와, 값 자리에 `{P_변수명}`이 들어간 한 행으로 구성합니다. 컬럼은 모두 Numeric입니다.
2. **Python Transform**: 스크립트가 다음을 수행합니다.
   - `{P_변수명}`이 치환된 JSON을 만들어 엔드포인트에 `POST`
   - 응답의 `data` 배열을 DataFrame으로 변환
   - `Score`를 숫자로 변환하고 `Result`, `Grade` 컬럼 추가
   - 최종 결과를 `table = df`로 반환
3. **스키마**: 기존 52개 컬럼(`KEY` + 변수 47개 + 출력 4개)에 `Result`, `Grade`(TEXT) 2개를 더해 54개입니다.
4. **파라미터**: 변수 47개를 NUMERIC 파라미터로 선언합니다. 이름은 `P_` + 컬럼명이고, 기본값은 기존 샘플 요청 값을 0~10으로 제한한 값입니다.
5. **정리한 점**: 기존 고정 요청에 중복되어 있던 `R1_CF0600224` 키는 한 번만 보내도록 했고, `KEY`는 1로 고정했습니다.

기존에는 DataLibrary(공유 데이터 테이블 저장소)를 가리키는 연결(`linkedTableId`) 형태였는데, 파라미터와 Python Transform을 쓰려고 워크북 안에 완전한 정의를 두는 형태로 바꿨습니다.

### 3-4. 대시보드 위젯 구성

모든 위젯은 가로·세로 비율(0~1) 좌표로 배치합니다.

| 영역 | 위치 | 구성 |
| --- | --- | --- |
| 제목 | 상단 전체 | 텍스트 박스 1개 |
| 슬라이더 | 좌측 약 2/3 | 5열 × 10행 격자, 변수 47개 (마지막 열 3칸 비어 있음) |
| KPI | 우측 상단 | `신용점수` 라벨과 값 |
| 결과 행 | 우측 중단 | 불량확률, 정상확률, target 예측, 판정, 신용등급 구간 (라벨 + 값) |
| 점수 구간 띠 | 우측 하단 | 위험 / 주의 / 보통 / 양호 / 우수 / 최우수 색 구간 6개 |
| 안내 | 우측 최하단 | 사용 방법과 모델 정보 |

슬라이더 속성은 다음과 같습니다.

| 속성 | 값 |
| --- | --- |
| `Minimum` / `Maximum` | 0 / 10 |
| `ValueFormatString` | `#,##0.0` |
| `DashboardParameterName` | `P_` + 변수명 |
| `Title` | 변수명 |
| `ActionPartTriggerMode` | `Parameter` |

결과 박스는 데이터 모드 텍스트 박스이며 `columnname`으로 표시할 컬럼을 지정합니다.

### 3-5. exz 파일 패키징

`.exz`는 ZIP 형식이며 주요 구성은 다음과 같습니다.

| 경로 | 역할 |
| --- | --- |
| `Workbooks/<폴더>/<워크북>/workbook.json` | 워크북 전역 설정 |
| `.../datatables/<id>.json` | 데이터 테이블 정의 (소스, 변환, 스키마, 파라미터) |
| `.../dashboards/Dashboard1.json` | 위젯 목록, 파라미터, 런타임 설정 |
| `.../datatables.list`, `dashboards.list` | 포함된 데이터 테이블·대시보드 목록 |
| `.../mangling.txt` | 한글 이름과 파일 경로 매핑 |
| `DataLibrary/datatables` | 공유 데이터 테이블 저장소 (이번에는 비어 있음) |

레퍼런스와 기존 파일의 JSON 구조를 비교해 같은 형식으로 `Dashboard1.json`과 데이터 테이블 JSON을 생성한 뒤 다시 압축했습니다.

## 4. 지원 기능

- **실시간 입력 조절**: 슬라이더 47개로 신용 변수를 0~10 범위에서 직접 바꿉니다. 슬라이더를 움직이면 모델이 다시 호출됩니다.
- **점수와 확률 확인**: 신용점수(0~1000), 불량확률, 정상확률을 동시에 봅니다.
- **target 예측**: `prediction(TARGET)`을 0(정상) 또는 1(불량)로 표시합니다.
- **판정**: target 값에 따라 `정상` / `불량` 문구로 표시합니다.
- **신용등급 구간**: 점수를 구간으로 분류해 보여줍니다. 아래 기준은 예시입니다.

| 점수 | 등급 구간 |
| --- | --- |
| 900 이상 | 최우수 |
| 800 ~ 899 | 우수 |
| 700 ~ 799 | 양호 |
| 600 ~ 699 | 보통 |
| 500 ~ 599 | 주의 |
| 500 미만 | 위험 |

- **점수 구간 띠**: 0~1000 척도와 구간별 색을 참조용으로 함께 표시합니다. 현재 점수 위치를 표시하는 마커는 없습니다.
- **재현 가능한 배포**: 워크북을 `.exz`로 내보내 버전으로 관리하고 다른 환경에서 가져올 수 있습니다.

## 5. 사용 방법

### 5-1. 기본 사용

1. Panopticon Designer에서 `261109_dashboard_v3_sliders.exz`를 가져옵니다.
2. Python Transform이 동작하도록 Panopticon의 Python 서버가 실행 중이고 `pandas`, `requests`가 설치되어 있는지 확인합니다.
3. 대시보드를 열고 슬라이더를 조작합니다.
4. 우측의 점수, 확률, target, 판정, 등급 구간이 갱신되는지 확인합니다.

### 5-2. 서버 버전이 다를 때 (26.1 환경)

번들의 `server_version.txt`에 적힌 버전이 서버 버전보다 높으면 가져오기가 거부됩니다.  
원본 번들(`261109_dashboard_v3_sliders.exz`)은 `2609.1.0.36042`로 기록되어 있어 버전 **26.1.0.35462** 서버에서는 오류가 발생합니다.

이를 위해 서버 버전에 맞게 수정한 `261110_슬라이더적용_v2_server26.1.exz`를 별도 제공합니다.

| 항목 | 원본 | 26.1 호환본 |
| --- | --- | --- |
| 파일명 | `261109_dashboard_v3_sliders.exz` | `261110_슬라이더적용_v2_server26.1.exz` |
| 대상 서버 버전 | 2609.1.0.36042 이상 | 26.1.0.35462 |

**수정한 곳 (3군데)**

| 위치 | 수정 내용 |
| --- | --- |
| 최상위 `server_version.txt` | `2609.1.0.36042` → `26.1.0.35462` |
| `metadata.json`의 `Version` 값 | `2609.1.0.36042` → `26.1.0.35462` |
| `DataLibrary/datatables` 내부 압축 파일의 `server_version.txt` | `2609.1.0.36042` → `26.1.0.35462` |

버전이 다른 서버 환경을 추가로 지원해야 한다면 같은 방식으로 세 곳의 버전 문자열을 대상 서버 버전으로 교체한 뒤 `.exz`로 재압축합니다.

## 6. 문제 해결 기록

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 판정·등급 박스에서 `Aggregate binding failed: column ... has bad type` | 텍스트 컬럼 박스의 가중치 컬럼(`WeightColumnName`)을 텍스트 컬럼 자신으로 지정. 가중치는 숫자형이어야 함 | 텍스트 컬럼 박스의 가중치 컬럼을 숫자 컬럼(`Score`)으로 변경 |

운영 중 값이 나오지 않을 때 확인할 항목은 다음과 같습니다.

- Python 서버 기동 여부, `requests` 설치 여부
- 엔드포인트 인증 필요 여부 (현재 스크립트는 인증 헤더 없이 호출)
- 슬라이더 이름과 파라미터 이름(`P_` + 컬럼명), 스크립트의 `{P_...}` 자리 표시자가 모두 일치하는지

## 7. 한계와 개선 방향

| 항목 | 현재 | 개선 방향 |
| --- | --- | --- |
| 점수 위치 표시 | 구간 띠만 있고 현재 점수 마커 없음 | Bullet Graph 등 시각화 컴포넌트로 점수 위치 표시 |
