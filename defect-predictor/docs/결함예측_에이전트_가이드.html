  • 알고리즘: Gradient Boosted Trees (GBT) Regression
  • 탐색 조합: 총 792 combinations grid search 수행
  • number of trees: min 50 ~ max 500 (step: 10)
  • maximal depth: min 3 ~ max 15 (step: 7)
  • learning rate: min 0.001 ~ max 0.1 (step: 8)

Section 02
에이전트 설계 개요

LLM이 결함률을 직접 추측하지 않고, 언어 처리(자연어 추출/정규화)와 결과 해설만을 담당하며 정밀 수치 연산은 검증된 ML API가 수행하는 철저한 역할 분리형 구조입니다.

🚫
추측 절대 금지
질의에 명시되지 않은 필드는 임의로 채우지 않고 반드시 null 처리합니다. LLM이 직접 수치를 보완하거나 기본값을 가정하지 않습니다.
🔍
모호성 격리
"약간 높음", "평소대로"와 같은 모호한 발화는 null 처리 및 ambiguous_fields에 기록 후 정확한 수치를 되묻습니다. 모호 필드는 세션 슬롯에서도 즉시 삭제합니다.
🔄
세션 맥락 유지 (멀티턴)
이전 대화에서 확인된 슬롯은 유지하며, 새로운 입력 및 정정 사항을 점진적으로 병합합니다. 명시적으로 덮어쓰기 전까지 기존 값이 보존됩니다.

Section 04
파이프라인 구조 및 동작 흐름

자연어 질의 수신부터 슬롯 채우기, 다단계 검증, ML API 추론, LLM 해설 및 응답 반환까지의 전체 아키텍처 흐름도입니다.

8단계 파이프라인 핵심 흐름:
• 1~3단계 (추출 & 병합): SDC LLM 구조화 출력 → 개별 필드 조기 검증(validate_provided_fields) → 세션 병합 (부족 시 need_more_info 되묻기)
• 4~6단계 (검증 & 추론): Pydantic 최종 검증(DefectRateInput) → JSON Payload 생성 → AI Hub ML Client 호출 (실패 시 endpoint_error)
• 7~8단계 (해설 & 반환): 예측 결함률(%) 수신 → LLM 공정 인자 민감도 해설 생성 → status: ok 최종 사용자 응답

Section 06
Golden Set 테스트 결과 및 주요 개선

Golden Set v3 기반 회귀 테스트를 수행한 결과, 초기 93.3% (56/60 통과)에서 주요 병목 원인을 분석하고 프롬프트 및 파이프라인 로직을 수정하여 100% 통과를 달성했습니다.

C08, P06 — 수량 누락 오류
원인: "533개" 등 명확한 단위가 있는 첫 발화 수치를 항목명이 없다는 이유로 폐기하여 수량 누락.
조치: 단위-필드 1:1 매칭 규칙 도입 — "개"는 planned_quantity의 유일한 후보이므로 항목 라벨이 없어도 즉시 매칭하도록 프롬프트 완화.
A06 — 과도한 모호성 판단
원인: "습도가 약간 높고 마모가 심함" 질의에 대해 언급되지 않은 필드까지 12개 전체를 모호(ambiguous)로 판단.
조치: 미언급 필드와 모호 필드 명확 분리 — 언급되지 않은 필드는 null(누락), 수치 없이 성향만 언급된 필드만 ambiguous_fields로 격리.
What-if 세션 오동작
원인: 기존 습도(54.49%) 세션 후 "습도가 꽤 높아지면?" 질의 시, 추출값이 null이라 기존 세션의 54.49%가 유지되어 예측이 바로 실행되는 오류.
조치: pipeline.py 로직 수정 — 추출된 ambiguous_fields에 포함된 필드는 세션 슬롯에서 즉시 pop하여 재질문되도록 변경.
I08 / 슬롯 미완성 상태 조기 검증 부재
원인: 슬롯이 12개 채워지기 전에는 Pydantic 검증이 돌지 않아 잘못된 공급사 코드(SIM-SUP-D)가 세션에 저장.
조치: validate_provided_fields 도입 — 슬롯 완성 여부와 관계없이 값이 들어온 필드는 세션 저장 직전 개별 유효성을 즉시 검증하여 위반 시 세션 저장 차단.
Section 07
프롬프트 엔지니어링 및 수정 내역

프롬프트의 복잡도와 중복을 줄이고 LLM의 구조화된 추출 신뢰도를 극대화하기 위해 프롬프트 v2로 리팩토링을 단행했습니다.

7.1 프롬프트 최적화 주요 변경점 (v1 → v2)
분량 약 35~40% 감소: 불필요한 번호 체계(2-1 등)를 제거하고 명확한 기능별 섹션 제목으로 개편.
불확실성 처리 2분기(A/B) 통합: A분기(필드 특정, 값 불명) → 값은 null + ambiguous_fields에 필드명 등록. B분기(값은 존재, 대상 필드 불명) → 값 폐기 + notes에만 사유 기록.
단위 환산표 단일화: 길이(m/cm/µm → mm), 두께(m/cm/mm → µm), 시간(주 → 일) 등 단위 환산 정의를 단일 표로 통합.
다중 조건 비교 처리: "라인1과 라인2를 비교해줘"와 같은 질의는 records 배열에 2개의 개별 객체로 분리하여 추출하도록 명세화.
# 프롬프트 v2 핵심 지침 발췌 (aihub/prompt/extractor_v2.txt) [기본 원칙] 1. 추측 절대 금지: 질의에 없는 필드는 null로 둡니다. 2. 단위 정규화: 환산표에 따라 기준 단위(mm, µm, 일 등)로 변환하여 수치만 입력합니다. 3. 불확실성 처리: - 특정 필드의 상태/성향만 언급된 경우: 해당 필드 null + ambiguous_fields에 추가 - 항목명과 단위가 없어 필드를 특정할 수 없는 수치: 값 버림 + notes에 기록 4. 다중 조건 비교: "라인1과 라인2를 비교해줘"와 같은 질의는 records 배열에 2개의 개별 객체로 분리하여 추출합니다.

What-if Simulation "다른 조건은 그대로 두고 공구 마모도만 90%로 올리면 결함률이 어떻게 변해?" 처럼 특정 공정 변수 변화에 따른 결과를 가상 시뮬레이션하는 기능.
Pydantic Python 타입 어노테이션을 사용하여 데이터의 유효성 검증(Validation)과 직렬화를 고속으로 수행하는 라이브러리. DefectRateInput 모델이 12개 필드의 타입·범위·허용값을 검증한다.
SDC LLM Gateway Siemens Digital Connect 기반 LLM 호출 게이트웨이. 추출·해설 프롬프트 실행에 사용되며 JSON 구조화 출력을 지원한다.
