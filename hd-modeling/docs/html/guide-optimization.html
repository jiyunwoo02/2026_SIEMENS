프로세스 개요

GBT 분류 모델을 목적 함수로 삼아 Prescriptive Analytics(Evolutionary)가 목표 조건(target)을 달성하는 최적 공정 파라미터 1세트를 탐색합니다. 결과는 현장에서 실제로 적용 가능한 공정조건 조합으로 반환됩니다.

target 매크로 (0 / 1)
→
학습 데이터 로드
→
GBT 분류 모델
→
Prescriptive Analytics
→
최적 공정조건 1세트

target 파라미터

GET 쿼리스트링으로 주입. AI Studio 배포 프로세스 내에서 매크로로 전달됩니다.

1
불량 최소화
고결함(1) 확률을 최소화하는 공정조건 탐색.
결함을 줄이기 위한 개선 조건을 추천한다.

0
위험 조건 탐색
정상(0) 확률을 최소화하는 공정조건 탐색.
결함이 발생하기 쉬운 위험 조건을 역탐색한다.

설계 원칙: LLM은 intent 문자열만 판단합니다. target 값("0"/"1") 변환은 INTENT_TO_TARGET 사전이 담당하여 LLM 환각을 방지합니다.

defect-advisor Intent 분기

최적화 API는 defect-advisor에서만 사용됩니다. intent에 따라 회귀 API, 최적화 API 호출 여부와 target이 결정됩니다.

intent회귀 API최적화 APItarget설명
predict✓——결함률 예측만
predict_and_optimize✓✓"1"예측 + 개선 조건
predict_and_find_risk✓✓"0"예측 + 위험 조건
optimize_reduce_defect—✓"1"개선 조건만
optimize_find_defect_risk—✓"0"위험 조건만
clarify———추가 정보 요청

부분 성공 처리

predict_and_optimize / predict_and_find_risk 에서 최적화 API가 실패해도 status="ok"로 응답합니다.

{
  "status": "ok",
  "prediction": { "defect_rate_pct": 1.65 },
  "optimization": null,
  "errors": ["optimization timeout after 180s"]
}
